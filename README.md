# Corevia 판매장려금 지급 통제

> 통제 규칙은 프로그램이 계산하고, AI는 설명만 하며, 승인과 지급은 사람이 합니다.

이름이 다른 관련 거래처로 지급을 나눠 **승인 한도를 피하는 것**과 **확인되지 않은 계좌로 지급되는 것**을 막는 판매장려금 지급 통제 시스템입니다. AX 인재전쟁 예선(삼일PwC 출제, 2026.11.11~13) 개인 프로젝트로, 가상기업 Corevia의 대리점 50곳 · 지급 이력 240건 · 승인 권한 정책에서 출발했습니다.

> **원본 데이터는 이 저장소에 포함하지 않았습니다.** 대회 운영 측이 제공한 가상기업 자료라 공개 허락을 확인하지 못했기 때문입니다. 그래서 저장소만 받아서는 실행되지 않습니다. 동작은 [`증거/`](증거/)의 실행기록으로 확인할 수 있고, 시연 영상은 요청하시면 제공합니다.

## 무엇을 막나 — 세 가지 사례

### 1. 승인 한도 우회: 관련자 합산
대표자·주소·정산계좌 중 2개 이상이 같으면 관련자로 보고, 이어지는 관계까지 따라 한 그룹으로 묶어 같은 귀속월 금액을 더합니다(200만원 이하 영업지원팀, 초과 영업임원).

| 같은 원본을 두 방식으로 계산 | 건별로 보면 | 관련자로 합치면 |
|---|---|---|
| 2026-06 미지급 40건 중 영업임원 대상 | 0건 | **3건** (D-011·D-024·D-037, 합계 3,888,097원) |
| 지난 승인 196건 중 영업임원이 필요했던 건 | 0건 | **15건 · 22,238,349원** (현재 기준 재검토 대상) |

### 2. 지급 전 계좌 통제
직접 검수 중 **계좌 없이도 ‘모의 지급 완료’가 되고, 아무 문자열 계좌도 통과하는 결함**을 발견해 추가한 통제입니다.

- 은행·계좌 형식(국내 숫자 10~15자리) 점검. 범위 밖·해외 계좌는 오류로 단정하지 않고 확인 보류
- 소유 확인 방법·근거가 기록돼야 지급
- 승인 뒤 정산계좌가 바뀌면 승인 무효화 → 재검토. 정산계좌는 관련자 판정 항목이라 그룹과 합계가 다시 계산됨(예: RB-00054 3,888,097원 → 2,562,561원, D-037 제외)

### 3. AI 출력 검증
AI 요약이 금액·승인자·상태를 틀리게 말하는지 실제 모델(Gemini 3.5 Flash-Lite)로 5회 평가했습니다. 지시문 보강은 오류를 5건으로 늘렸고, AI에 넘기는 입력을 영문 필드 이름 대신 한국어 항목으로 바꾼 최종 회차에서 5개 사례 모두 사실 오류 0건이었습니다. → [`증거/AI_설명_평가.md`](증거/AI_설명_평가.md)

## 작동 범위
- **실제 작동**: 관련자 판정, 귀속월 합산·승인자 결정, 중복 합산 방지, 계좌 변경 시 승인 무효화·재승인 차단, 수취계좌 점검과 지급 차단, 승인 당시 조건 재비교, 확인 작업·재상신 규칙, 역할별 권한의 서버 확인과 거부 기록, SQLite 저장·충돌 방지, 이력 해시 연결 검사, 과거 지급 점검, Gemini 요약
- **모의 처리**: 승인·거절, 소명 회신, 재무 판정, 계좌 소유 확인, 지급(실제 송금 없음), 역할 선택(로그인이 아니라 화면에서 고르는 값)
- **설계 단계(미구현)**: 실제 로그인과 신청자·승인자 분리, 은행 실명 조회·송금, 증빙 파일 검증

## 실행 방법 (원본 데이터가 있을 때)
Node.js 26 이상(내장 `node:sqlite` 사용), 별도 패키지 설치 없음.

1. 원본 CSV 4개(구분자 `|`)를 `data/source/` 아래에 둡니다.
   `master/m_agency_cv.csv`, `sales/sales_rebate_payment_cv.csv`, `financials/fin_collection_history_cv.csv`, `financials/fin_ar_aging_cv.csv`
2. 실행합니다.

```bash
node server.js            # AI 없이 실행 → http://127.0.0.1:3217
node start-gemini.cjs     # Gemini API 키를 입력받아 AI 요약까지 실행 (키는 파일에 저장하지 않음)
```

- 자동 점검 20종: `check-*.cjs`를 하나씩 실행합니다(통과하면 `PASS` 출력). 원본 데이터가 있는 환경에서 20종 모두 통과를 확인했습니다.
- 정적 체험판: `node build-static.cjs docs`로 서버 없이 브라우저에서 도는 체험판(기록은 브라우저에 저장, AI 꺼짐)을 만들 수 있습니다. 원본 데이터가 함께 들어가므로, 공개 허락을 확인한 뒤 게시할 예정입니다.

## 폴더
| 경로 | 내용 |
|---|---|
| `domain/` | 업무 규칙(관련자·합산·승인 흐름·계좌·확인 작업). 서버판과 체험판이 같이 씀 |
| `public/` | 화면 |
| `server/`, `server.js` | API·SQLite 저장·해시 연결 이력 |

| `증거/` | 대표 사례 실행기록(3개 사례 34단계), AI 설명 평가, 효과 지표 |
| `data/source/` | 원본 데이터 위치(저장소에는 미포함) |

## 만든 방식
코드는 AI 코딩 도구(Claude Code·Codex)가 작성했습니다. 저는 과제와 통제 범위를 정하고, 실제 담당자처럼 직접 써 보며 결함을 찾아 고치게 하고 다시 확인했습니다.
